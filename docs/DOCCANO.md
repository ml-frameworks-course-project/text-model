# Настройка doccano для разметки PromptShield

Инструкция рассчитана на двух разметчиков. Каждый работает на своём компьютере с Windows и Docker Desktop. В doccano выбирается метка для всего текста. Пояснения и фрагменты сохраняются в отдельных заметках каждого разметчика. Так их можно сопоставить после окончания независимой разметки.

Команды и порядок работы основаны на [инструкции по установке doccano](https://doccano.github.io/doccano/install_and_upgrade_doccano/) и [руководстве по импорту и экспорту](https://doccano.github.io/doccano/tutorial/). Данный сценарий ещё нужно проверить на пилотных примерах в установленной версии программы.

## 1. Подготовьте данные

1. Убедитесь, что в репозитории есть файл [`data/manual_candidates/annotation_input.jsonl`](../data/manual_candidates/annotation_input.jsonl).
2. Откройте [кодбук](CODEBOOK.md) и согласуйте его версию до начала разметки.
3. Передайте обоим разметчикам одинаковый `annotation_input.jsonl` и кодбук. В каждой строке есть `id`, `text` и пустой список `label`; исходной метки в файле нет.
4. Не открывайте до завершения независимой разметки `provenance_private.jsonl`, `selection_stats.json`, `stable_id_map.json` и `collect_candidates.py`: в них есть предполагаемые метки или параметры отбора.

Файлы с предварительными метками находятся в репозитории. До окончания разметки не открывайте их и не показывайте друг другу свои ответы.

## 2. Запустите doccano

Каждый разметчик выполняет следующие шаги на своём компьютере. У каждого будет своя установка doccano и локальный адрес для работы. После независимой разметки нужно сохранить экспорт и передать его для сравнения результатов.

1. Запустите Docker Desktop и дождитесь его готовности.
2. Откройте PowerShell и проверьте доступность Docker:

   ```powershell
   docker version
   ```

   Если команда не показывает сведения о сервере Docker, проверьте, что Docker Desktop запущен.

3. Загрузите образ:

   ```powershell
   docker pull doccano/doccano
   ```

4. Задайте пароль администратора для текущего запуска. Введите его без кавычек после запроса:

   ```powershell
   $doccanoPassword = Read-Host "Пароль администратора doccano"
   ```

   Ввод в этом варианте виден в окне терминала. Не включайте пароль в файлы репозитория и не отправляйте его вместе с результатами.

5. Создайте контейнер:

   ```powershell
   docker container create --name doccano-coursework `
     -e "ADMIN_USERNAME=admin" `
     -e "ADMIN_EMAIL=admin@example.com" `
     -e "ADMIN_PASSWORD=$doccanoPassword" `
     -v doccano-coursework-data:/data `
     -p 127.0.0.1:8000:8000 doccano/doccano
   ```

   `doccano-coursework` обозначает контейнер, а `doccano-coursework-data` хранит данные между его остановками. Адрес `127.0.0.1` означает, что браузер подключается к программе с этого же компьютера. `admin@example.com` является примером для локальной установки. Если имя контейнера или порт уже заняты, выберите другое имя или порт и используйте их последовательно в следующих командах.

6. Запустите контейнер:

   ```powershell
   docker container start doccano-coursework
   ```

7. Откройте в браузере `http://localhost:8000`, войдите под именем `admin` и паролем из шага 4. Если страница не открывается, посмотрите состояние и журнал:

   ```powershell
   docker ps -a
   docker logs doccano-coursework
   ```

Для последующих запусков используется команда из шага 6. Остановить контейнер можно командой `docker container stop doccano-coursework`. Не удаляйте том `doccano-coursework-data`, пока результаты не сохранены и не проверены. Запишите используемую версию doccano в журнал работ.

## 3. Создайте проект на каждом компьютере

Каждый разметчик создаёт один проект в своей установке doccano, например `PromptShield annotator 1` или `PromptShield annotator 2`.

На каждом компьютере:

1. На странице проектов нажмите `Create` и выберите задачу **Text Classification** или `DocumentClassification`, если интерфейс показывает техническое имя.
2. В настройках включите режим одного класса на запись, если он доступен. Для одного текста должна сохраняться только одна из меток ниже.
3. Добавьте метки с точными названиями `0`, `1` и `?`. Их значения определены в кодбуке. `?` используется для разбора и не является классом модели.
4. Добавьте текст кодбука в поле инструкции проекта, если оно доступно, либо держите файл `CODEBOOK.md` открытым отдельно.
5. Перейдите в `Dataset` → `Actions` → `Import Dataset`, выберите JSONL, укажите `text` в поле Column Data и `label` в поле Column Label, затем загрузите файл `annotation_input.jsonl`. На обоих компьютерах должна быть одна и та же версия файла.

Каждый размечает данные только в своём проекте. Не включайте автоматические подсказки или предварительные метки при ручной разметке.

## 4. Проверьте пилот до основной разметки

Не начинайте разметку всех 150 записей, пока не проверили импорт и экспорт на нескольких примерах.

1. На обоих компьютерах откройте одинаковые 5-10 текстов. Проверьте, что копии содержат одни и те же тексты, включая переносы строк.
2. Каждый разметчик на своём компьютере размечает те же примеры метками `0`, `1` или `?`. Проверьте, что второй выбор заменяет первый, а не добавляет вторую метку.
3. На каждом компьютере откройте `Dataset` → `Actions` → `Export Dataset` и экспортируйте результаты в JSONL. Сохраните файлы под разными именами, например `annotator_1.jsonl` и `annotator_2.jsonl`.
4. Проверьте содержимое экспортов: есть ли исходный `TXT-...`, полный текст и метка. Номер `doc_id`, созданный doccano, не считайте исходным `id`, пока соответствие не проверено.
5. Если исходный `id` не сохранился, составьте соответствие по **точному неизменённому `text`** с исходным `annotation_input.jsonl` и проверьте его для каждого экспорта. На момент подготовки инструкции в исходном файле 150 разных текстов и 150 разных `id`; после изменения входного файла эту проверку нужно повторить. При отсутствии или неоднозначности совпадения остановитесь и исправьте сопоставление до основной разметки.
6. Убедитесь, что две аннотации одного исходного `id` можно получить из разных экспортов. Не заменяйте первоначальные решения общей меткой.

После технической проверки проведите пилот кодбука на 20-30 общих примерах. Подробный порядок сравнения и разрешения расхождений приведён в кодбуке.

## 5. Записывайте пояснения отдельно

Для каждого примера разметчик должен указать метку, обоснование и при необходимости фрагмент. В режиме классификации наличие отдельного поля для такого пояснения и его видимость другим пользователям зависят от интерфейса и способа экспорта, поэтому не полагайтесь на них до проверки.

Надёжный вариант для пилота: каждый ведёт свою отдельную таблицу или JSONL с полями `id`, `annotator_id`, `label`, `evidence`, `reason`, `codebook_version`. В `evidence` для метки `1` скопируйте точный фрагмент из `text`; для `0` поле остаётся пустым. Для `?` в `reason` укажите, какой информации не хватает. Значение `id` переносите только после проверки сопоставления на шаге 4. Результат в заметках и метка в doccano должны совпадать.

Не размещайте независимые пояснения в общем чате или в доступном второму разметчику комментарии до завершения разметки. Время, потраченное на партию примеров, записывается отдельно в журнал работ, а не в разметку каждого текста.

## 6. Завершите разметку и соберите результаты

1. Каждый разметчик экспортирует свой проект в JSONL и сохраняет исходный файл без изменений. Для сравнения передайте оба экспорта одному участнику после завершения независимой разметки.
2. Сопоставьте записи по исходному `id`, затем объедините их с отдельными пояснениями каждого разметчика. Проверьте, что для каждого примера есть два ответа.
3. Посчитайте согласие и разберите разногласия согласно кодбуку. Добавьте итоговую метку и причину решения в отдельные поля; первоначальные ответы сохраните.
4. После независимой разметки добавьте сведения об источниках из `provenance_private.jsonl` по `id`. Не заменяйте ими ручные метки.
5. Перед включением в обучающие данные исключите неразрешённые примеры и повторно проверьте похожие формулировки.

Если экспорт не содержит нужные поля или текст изменился при импорте, сохраните пилот и устраните проблему до разметки всей выборки. Не подменяйте отсутствующий идентификатор номером строки после сортировки.
